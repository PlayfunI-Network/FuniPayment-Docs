- 後台示範：截圖是圖片，字級照後台原始碼（`C:\Users\LD\PycharmProjects\FuniPayment\web\src`，只讀）的 class 取，乘上截圖縮放（舞台寬 ÷ 截圖的 CSS 寬：login 1280、welcome 520、精靈 808、手機版都是 375）。
- 改完再用一段暫時的測試，拿真的 `resolveSteps` + `cameraTransform` 算出每一步的實際倍率，並檢查游標在不在畫面裡（沒有 commit）；截圖時也讀了畫面上實際的縮放（含鏡頭）做對照。

**重要發現：** `lib/camera.ts` 的 `NARROW_WIDTH` 是 640，精靈頁的舞台在 1280 寬只有 635 px，所以**桌機也會被乘上 `NARROW_BOOST` 1.35**：原本寫 `zoom: 1.6`、實際是 2.16 倍；寫 1.3 實際是 1.76 倍。精靈五個示範的倍率我都是先算出想要的實際倍率，再除以 1.35 寫進去（見第 5 節）。

## 2. 保留放大的地方

- **LoginDemo 第 1 步（1.65）**：登入頁截圖 1280 寬，桌機縮成 0.53 倍，按鈕字 7.4 px。截圖不能改，所以只能放大。手機上同一步也會放大（受按鈕寬度限制 1.28 倍），手機其實不需要，但後台示範的步驟兩種寬度共用（見第 5 節）。
- **精靈五個示範**：截圖 808 寬塞進 635 舞台（0.786 倍），後台 10.5–13 px 的字只剩 8–10 px，版面不能改。每個示範只放大一次，倍率是讓 caption 指的最小字到 12 px 左右的最小值。因為 `NARROW_BOOST`，放大的最小實際倍率是 1.35，所以第二、三、四、五步的「下一步」「建立」這類 14 px 按鈕會比最小需要的大一些。
- **FirstOrderDemo 桌機（1.12）**：fp 共用畫面寬版 880 px，embed 只有 10.8 px。任務檔規定只能改鏡頭，所以用最小倍率。改共用畫面的版面就能拿掉（見第 5 節）。
- **還是小於 11 px 的地方**：
  - setup-1 手機的狀態標籤（9.5 px）、setup-1「找不到我的伺服器？」桌機（10.4 px）、setup-5 摘要（9.8／10.3 px）：目標本身佔滿寬度，`zoomOn` 不讓它放得更大。
  - setup-4 第 1 步（9.4–9.8／9.9–10.3 px）：反過來，目標只有小開關，一放大手機就切掉付款方式名稱，所以留在全景。
  - 這些都要加新的目標才能解決（見第 5 節）。

## 5. 希望主 session 改的共用元件

1. **`lib/camera.ts` 的 `NARROW_BOOST` 會作用在桌機**：判斷用的是舞台寬度 < 640，但精靈頁在 1280 寬的舞台只有 635 px，所以桌機的放大也被乘上 1.35。後台示範在 < 600 時已經換手機截圖，手機加成應該只在用窄版的時候作用（例如改用 `NARROW_BELOW` 600，或讓 `DashboardDemo`、`DiscordDemo` 直接告訴鏡頭現在是不是窄版）。改了之後，`dashboard-demos.tsx` 精靈的 `zoom: 1.05`／`1.08` 要乘回 1.35（改成約 1.42／1.46），檔案開頭的註解有寫。
2. **後台示範的 `zoom` 不能分桌機／手機**：LoginDemo 第 1 步桌機需要 1.65，手機全景就有 12.7 px。希望 `DashboardStep` 能分開寫（例如 `zoom: { desktop: 1.65, mobile: 1 }`）。
3. **fp 共用畫面（`components/demos/shared/fp-screen.tsx`，payments 組）寬版 880 px**：embed 在 680 舞台只有 10.8 px。如果改成跟 home／get-paid 一樣 `LIST_W + 500`（要重量 `at` 的座標），FirstOrderDemo 就能整段全景。channel-automation-screen 的寬版也一樣，payments 組的 channel automation 示範應該有同樣的問題。
