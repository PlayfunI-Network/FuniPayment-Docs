# 回報：收款章節的示範（payments）

分支 `zoom-fix/payments`（從 `docs-v1` 的 `becd39f` 開出），worktree `../FuniPayment-Docs-zoom-payments`。

## 結論

8 個示範（含 `RecheckAllDemo` 共 9 條時間軸）**全部不放大**，桌機與手機每一步都是全景。字太小的地方用修版面解決，沒有一處保留放大：

- 有頻道列表的寬版（fp、頻道自動化、過期、補查）原本是 240 + 640 = 880 寬，桌機舞台 678 px 只畫成 0.77 倍，embed 的 14 px 字是 10.8 px、分類名稱 12 px 是 9.2 px，全景不夠。改成視窗 480 寬（畫布 720），畫成 0.94 倍：embed 13.2 px、分類名稱 11.3 px。
- 手機有三個示範的字原本就不到 11 px（放大也被 `zoomTo` 限制在 1.05 倍救不起來），把窄版畫布做窄：歷史紀錄 460 → 420、購買人資訊 400 → 360、`/payment create` 400 → 360。

## 怎麼量的

- dev server：`npx next dev --webpack -p 3203`。
- `docs/zoom-fix/reports/payments/measure.mjs`（不 commit）：Playwright 開真實頁面，`page.clock` 控制時間軸，每個 caption 那一步截圖，並讀畫布裡每段字的 computed font-size × 畫布縮放比例（舞台寬 ÷ 畫布寬）＝ 全景下顯示的字高，也記下當時鏡頭的 transform。
- 舞台寬度：viewport 1280 → **678 px**；viewport 375 → **341 px**。
- 座標：`/dev/fp`，以及暫時的 `app/dev/payments-measure`（量完刪掉，不 commit），用 `points.mjs`（不 commit）讀按鈕、選單、輸入框的 `getBoundingClientRect`，1280 和 375 兩種 viewport 都量。

下面的「字高」都是全景（鏡頭 1 倍）時實際顯示的 px，桌機／手機。

`components/demos/shared/` 被 `FirstOrderDemo`（`/getting-started/first-order`）和 `HomeDemo`（`/`）用到，兩頁都截圖確認過：
