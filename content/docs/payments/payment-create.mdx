開單時就把付款方式和金額一起填好，不經過選單，機器人直接建立訂單。顧客知道自己要怎麼付時，可以自己用這個指令開單；管理員也能用它替某位顧客開單。

<PaymentCreateDemo />

## 誰可以用

- 後台的「可建立訂單的身分組」沒有設定時，伺服器裡每個人都能用。
- 有設定的話，只有擁有其中一個身分組的人，或是有「管理員身分組」的人可以用。
- 「指定付款者」只有管理員身分組能填。

這兩個身分組都在後台設定，見[設定：基本](/dashboard/settings-basic)。

## 使用步驟

<Steps>
<Step>

### 輸入指令

在指令頻道或訂單頻道輸入 `/payment create`，選「付款方式」、填「金額」後送出。要開發票的話可以順便填「統一編號」和「發票抬頭」。

</Step>
<Step>

### 確認購買人資訊

機器人回一則只有你看得到的「📋 購買人資訊確認」。按「✏️ 填寫/修改資訊」填好姓名、電子郵件和電話，再按「確認並獲取付款碼」。填過一次，下次會自動帶入。詳見[購買人資訊與實名規定](/payments/buyer-info)。

</Step>
<Step>

### 訂單建立

那則訊息先變成「✅ 資訊確認中，請稍候...」，接著機器人在頻道貼出訂單，上面有付款編號、手續費、付款金額和付款期限。

</Step>
</Steps>

## 參數

| 參數 | 必填 | 說明 |
|---|---|---|
| 付款方式 | 是 | 「銀行轉帳」「四大超商條碼繳費」「7-11 ibon 代碼繳費」「全家 FamiPort 代碼繳費」「萊爾富 Life-ET 代碼繳費」五選一。Discord 上的說明是「請選擇付款方式」。 |
| 金額 | 是 | 訂單金額，整數，要大於 0，不含手續費。Discord 上的說明是「請輸入付款金額」。 |
| 我的姓名 | 否 | 購買人姓名，會先填進購買人資訊。Discord 上的說明是「(選填) 請輸入您的姓名」。 |
| 我的信箱 | 否 | 購買人電子郵件，用法同上。Discord 上的說明是「(選填) 請輸入您的信箱」。 |
| 我的電話 | 否 | 購買人電話，用法同上。Discord 上的說明是「(選填) 請輸入您的電話號碼」。 |
| 備註 | 否 | 跟著訂單送到速買配，訂單訊息上不會顯示。Discord 上的說明是「(選填) 請輸入備註」。 |
| 統一編號 | 否 | 只能填數字，會顯示在訂單訊息的「統一編號」。Discord 上的說明是「(選填) 請輸入統一編號」。 |
| 發票抬頭 | 否 | 會顯示在訂單訊息的「發票抬頭」。Discord 上的說明是「(選填) 請輸入發票抬頭」。 |
| 指定付款者 | 否 | 限管理員身分組。訂單記在這位成員名下，購買人資訊也帶入他存過的資料。Discord 上的說明是「[管理員] 協助顧客開設付款訂單」。 |

只有在後台開啟的付款方式能用，手續費照後台設定計算，見[設定：付款方式與手續費](/dashboard/settings-payment)和[手續費](/reference/fees)。

## 會看到什麼

三類付款方式的訂單訊息不一樣：

- 銀行轉帳：有「銀行代碼」和「銀行帳號」，照著轉帳。
- 四大超商條碼：條碼圖片貼在訊息裡，另有「點我查看付款教學」連結。
- 7-11、全家、萊爾富代碼：有「付款超商」和「繳費代碼」，另有「點我查看付款教學」連結。

同一張訂單也會私訊給付款者，後台有設日誌頻道的話也會收到一份。付款者關掉伺服器成員的私訊就收不到。四大超商條碼的私訊和日誌那份沒有附條碼圖片，條碼只在頻道裡那則訂單訊息上。

在開單分類的頻道裡開單時，訂單建立後頻道會換成「待付款時」的名稱和分類。/payment create 沒有選付款方式這一步，所以不會用到「選擇付款方式時」的設定。見[訂單頻道自動改名與移動](/payments/channel-automation)。

## 常見狀況

<Callout title="指令被拒絕">
- 「付款金額必須大於 0！」：金額填了 0 或負數。
- 「此商家目前沒有開放」開頭的訊息：選的付款方式在後台關著，換一種或請商家打開。
- 「抱歉，您沒有權限建立付款訂單。」：後台設了可建立訂單的身分組，你沒有其中任何一個。
- 「您只能為自己建立付款訂單喔！」開頭的訊息：沒有管理員身分組卻填了「指定付款者」。
- 「此伺服器的收款功能目前已暫停，暫時無法建立新訂單。」：這個伺服器的收款目前暫停中。
- 「您無法在此頻道使用此指令」開頭的訊息：後台設了指令頻道，這個頻道不在裡面，也不在開單分類下。

其他原因見[指令不能用](/troubleshooting/command-errors)。
</Callout>

<Callout type="warn" title="出現「訂單建立失敗...」">
訊息裡的「錯誤訊息：」會寫出原因，例如「速買配服務連線異常，請聯繫管理員再試一次」。如果是「此商家目前沒有開放此付款方式，請聯繫管理員再試一次」，代表這種付款方式在速買配還沒開通，機器人會自動在後台關掉它，並私訊伺服器擁有者。速買配回傳的其他錯誤見[速買配錯誤代碼](/troubleshooting/smilepay-errors)。
</Callout>

<Callout title="按了「取消操作」">
訊息會變成「操作已取消！」，訂單不會建立。要付款就重新輸入 `/payment create`。
</Callout>
