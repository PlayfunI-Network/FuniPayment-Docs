建立訂單前，機器人會先請付款者確認姓名、電話和電子郵件。用 /fp 時，這一步在顧客確認付款方式之後；用 /payment create 時，送出指令後就會出現。

<BuyerInfoDemo />

## 為什麼要填

這是金流平台的規定，畫面上的說明是這樣寫的：

> 根據金流平台相關規定，自 2026/04/23 後之所有訂單
> 消費者需提供 **__真實姓名、電話__** 等資料以符合相關法規
> 造成不便還請見諒！🙏

三個欄位都要填，「確認並獲取付款碼」才按得下去。

## 誰可以按

付款者本人，以及有「管理員身分組」的人。其他人按下去，機器人只會回一則他自己看得到的「你沒有權限操作此訂單。」

用 /payment create 時，這個畫面只有輸入指令的人看得到。管理員用「指定付款者」替顧客開單的話，畫面是管理員在看，帶入的是那位顧客存過的資料。

## 使用步驟

<Steps>
<Step>

### 打開表單

按「✏️ 填寫/修改資訊」，會跳出「填寫購買人資訊」表單。

</Step>
<Step>

### 填三個欄位

「您的姓名」和「電子郵件(Email)」最多 50 個字，「電話號碼」最多 20 個字，三個都必填。填好按「提交」。

</Step>
<Step>

### 確認並取得付款碼

畫面換成你填的資料。確認沒錯就按「確認並獲取付款碼」，機器人開始建立訂單。

</Step>
</Steps>

## 資料會存在哪裡

按下「確認並獲取付款碼」時，資料會存起來，跟著你和這個伺服器。下次在同一個伺服器開單，三個欄位會自動帶入，要改再按「✏️ 填寫/修改資訊」。換到別的伺服器要重新填一次。

用 /payment create 時，「我的姓名」「我的信箱」「我的電話」三個參數有填的話，會蓋過存著的那一份，按下確認後再存起來。

資料會跟著訂單送到速買配。商家在後台打開單筆訂單的明細時看得到完整資料，訂單列表上則會遮掉一部分，見[訂單列表與訂單明細](/dashboard/orders)。

## 常見狀況

<Callout title="「確認並獲取付款碼」是灰色的">
三個欄位還有沒填的。沒填的欄位會顯示「⚠️ 尚未填寫」，按「✏️ 填寫/修改資訊」補上就好。
</Callout>

<Callout title="不想付了">
/payment create 的畫面按「取消操作」，訊息會變成「操作已取消！」。/fp 的畫面按「上一步」，會回到確認付款方式那一步，可以從那裡「取消重選」。
</Callout>
