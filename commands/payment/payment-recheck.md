# /payment recheck

## 重新檢查付款狀態 (payment recheck)

### 指令概述

`/payment recheck` 是一個專為管理員設計的指令，用於手動重新檢查付款訂單的狀態。當系統未自動更新訂單狀態，或客戶表示已完成付款但系統尚未反映時，此指令特別有用。

![payment recheck 指令介面](https://i.imgur.com/example10.png)

### 使用權限

* **僅限管理員使用**：此指令只能由具有管理員權限的用戶使用

### 指令參數

| 參數            | 說明              | 必填 |
| ------------- | --------------- | -- |
| `smilepay_id` | 要檢查的付款訂單編號      | ✗  |
| `scan_all`    | 是否檢查伺服器內所有未付款訂單 | ✗  |

> **注意**: 若在票務頻道中使用且未提供訂單編號，系統將自動檢查該頻道中最後一筆未付款訂單

### 使用場景

#### 何時使用此指令？

1. **客戶表示已付款但系統未更新**：客戶提供付款證明，但系統尚未自動更新訂單狀態
2. **系統異常**：懷疑系統未正確接收速買配回傳的付款通知
3. **批量檢查**：需要一次性檢查多筆可能已付款但未更新的訂單

### 使用步驟

#### 1. 檢查單一訂單

指定訂單編號進行檢查：

```
/payment recheck smilepay_id:123456789
```

系統將向速買配 API 發送請求，確認該訂單的實際付款狀態。

#### 2. 檢查頻道最後一筆訂單

在票務頻道中，不帶參數直接使用指令：

```
/payment recheck
```

系統將自動檢查該頻道中最後一筆標記為未付款的訂單。

#### 3. 批量檢查所有未付款訂單

使用 `scan_all` 參數批量檢查伺服器內所有未付款訂單：

```
/payment recheck scan_all:1
```

> **警告**：此操作可能需要較長時間完成，請謹慎使用

### 檢查結果說明

系統檢查後將返回以下幾種可能的結果：

#### 訂單已付款

如果檢查發現訂單已完成付款，系統將：

1. 更新資料庫中的訂單狀態為「已付款」
2. 發送付款完成通知至原訂單頻道
3. 發送付款完成通知至用戶私訊
4. 記錄交易完成至日誌頻道
5. 自動執行相關頻道重命名和移動操作（若伺服器啟用此功能）

#### 訂單未付款

如果檢查發現訂單尚未付款，系統將返回訊息：

```
付款訂單 #123456789 經查詢尚未付款，也可能已過期或不存在。
```

#### 訂單不存在或已過期

如果訂單已過期或不存在，系統將返回訊息：

```
付款訂單 #123456789 已過期或不存在，無法進行查詢。
```

#### 批量檢查結果

批量檢查完成後，系統將顯示摘要：

```
所有未付款訂單更新完畢！
- 更新成功：X 筆
- 尚未付款：Y 筆
```

### 執行頻率考量

由於速買配 API 有請求頻率限制，系統在執行批量檢查時會自動控制請求速率，這可能導致操作需要較長時間完成：

* 單一訂單檢查：通常在幾秒內完成
* 批量檢查：每筆訂單間隔 1 秒，50 筆訂單約需 1 分鐘

### 常見問題解答

#### Q: 訂單明明已付款，為何重新檢查仍顯示未付款？

A: 可能原因：

* 付款尚未在銀行/超商系統中處理完成
* 付款方式有誤或金額不符
* 訂單已過期

#### Q: 批量檢查時卡在「正在檢查未付款訂單...」？

A: 批量檢查處理大量訂單需要時間，請耐心等待。系統每 5 筆訂單會更新一次進度。

#### Q: 是否可以檢查已過期的訂單？

A: 不可以。一旦訂單被標記為過期，將無法使用此指令重新檢查。如有特殊情況，請聯繫系統管理員。

#### Q: 檢查後顯示已付款，但客戶尚未收到通知？

A: 系統會自動嘗試發送通知，但如果用戶關閉了私訊功能，將無法收到私訊通知。請建議客戶檢查頻道訊息或開啟私訊功能。

### 系統運作原理

當執行重新檢查時，系統會：

1. 向速買配 API 發送請求，獲取訂單實際狀態
2. 若訂單已付款，系統會接收付款資料並更新本地資料庫
3. 處理相關通知和自動化操作

這個過程與系統正常接收付款回調的邏輯相同，唯一區別是由管理員手動觸發，而非由速買配自動回調。

### 安全提醒

* 此指令僅應在必要時使用，大部分情況下系統會自動更新訂單狀態
* 批量檢查功能應謹慎使用，避免不必要的 API 請求
* 訂單狀態變更將記錄在系統日誌中，包含執行操作的管理員資訊
